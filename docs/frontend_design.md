# 前端设计文档

## 前端设计目标

前端目标是让风险验证过程清晰可见。页面需要展示执行按钮、执行结果、风险等级、事件证据、恢复校验和报告导出结果，适合课堂演示和截图。

## 页面结构

页面采用左侧深色导航栏和右侧主内容区。主内容区包含顶部标题栏、消息提示区域和页面内容。统计数据使用卡片，风险列表使用表格，风险等级使用彩色标签。

## 页面路由

- `/`：仪表盘
- `/baseline`：基线文件
- `/events`：风险事件
- `/scan`：扫描检测
- `/simulate`：模拟风险
- `/restore`：文件恢复
- `/reports`：报告导出

## API 接口

- `GET /api/status`
- `POST /api/demo-init`
- `POST /api/baseline/init`
- `POST /api/scan`
- `POST /api/simulate`
- `POST /api/restore`
- `POST /api/report`
- `POST /api/reset`
- `GET /api/baseline`
- `GET /api/events`

## 前后端交互流程

前端通过原生 `fetch` 调用 API。`actions.js` 统一封装请求、消息提示和 JSON 结果渲染。后端返回统一结构：`success`、`message`、`data`，前端根据 `success` 显示成功或失败消息。

## 可视化展示方式

风险等级使用 `LOW`、`MEDIUM`、`HIGH`、`CRITICAL` 标签。仪表盘使用横向分布条展示等级数量。风险事件表格支持筛选和点击展开详情。

## 仪表盘设计

仪表盘显示项目说明、受保护文件数、风险事件总数、HIGH 数量、CRITICAL 数量、最近检测时间、风险等级分布和最近 5 条事件。快捷按钮可以完成创建演示环境、初始化基线、执行扫描和生成报告。

## 风险事件页面设计

事件页面展示风险等级、分值、类型、文件路径、证据、建议和检测时间。点击事件行后展开 old_hash、new_hash、old_size、new_size、完整 evidence 和 suggestion。

## 恢复页面设计

恢复页面提供相对路径输入框和恢复按钮。页面说明恢复路径禁止路径穿越，只允许恢复到演示目录。恢复成功后展示哈希校验结果。

## 报告导出页面设计

报告页面提供 JSON、CSV、HTML 导出按钮，并显示输出路径。HTML 报告可通过页面按钮打开，便于截图放入 PDF。

## 前端如何增强执行结果和风险展示

前端将每一步操作结果及时反馈到消息提示和结果框中，让用户知道操作是否成功。风险等级颜色、分值、证据和建议能帮助观察者理解为什么一个事件被评为高风险或严重风险。
