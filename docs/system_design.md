# 系统设计文档

## 设计目标

系统目标是通过编程实现一个本地敏感文件风险验证平台，让异常删除、篡改、新增可疑扩展名文件和批量变化能够被检测、评分、记录、恢复和展示。

## 系统架构

系统采用分层架构：核心检测引擎负责扫描和检测，SQLite 负责持久化，CLI 负责命令行演示，Flask Web 负责可视化，报告模块负责导出 JSON、CSV 和 HTML。

## 后端模块划分

- `scanner.py`：扫描受保护目录，计算 SHA-256。
- `baseline.py`：初始化数据库并保存基线。
- `detector.py`：比较基线与当前快照。
- `risk_engine.py`：计算分值、等级、证据和建议。
- `backup.py`：备份、恢复和哈希校验。
- `reporter.py`：事件持久化和报告导出。
- `demo.py`：演示数据和安全模拟。
- `cli.py`：命令行入口。

## 前端模块划分

- `base.html`：统一左侧导航、顶部标题和内容区域。
- `dashboard.html`：统计卡片、风险分布、最近事件、快捷操作。
- `baseline.html`：基线文件表格与筛选。
- `events.html`：风险事件表格与详情展开。
- `scan.html`：扫描操作和本次结果。
- `simulate.html`：安全模拟按钮。
- `restore.html`：恢复输入与校验结果。
- `reports.html`：报告导出与查看。

## 数据流

1. 创建演示文件。
2. 扫描受保护目录生成 `FileSnapshot`。
3. 保存基线到 `baseline_files`。
4. 复制文件到 `data/backups`。
5. 执行模拟风险。
6. 再次扫描当前状态。
7. 与基线比较生成变更。
8. 风险引擎生成 `RiskEvent`。
9. 保存事件到 `risk_events`。
10. Web 和报告模块读取事件进行展示。

## 业务流程

初始化流程：创建演示环境，扫描目录，保存基线，备份文件。  
检测流程：扫描当前目录，对比基线，识别变化，计算风险，保存事件。  
恢复流程：校验相对路径，从备份复制文件，重新计算哈希，与基线哈希比较。  
报告流程：读取风险事件，导出 JSON、CSV 和 HTML。

## 数据库设计

`baseline_files` 保存文件基线，包括路径、大小、修改时间、哈希和敏感等级。  
`risk_events` 保存风险事件，包括事件类型、哈希变化、分值、等级、证据和建议。  
`backups` 保存备份路径、基线哈希和备份时间。

## 风险评分规则

风险评分采用累加规则，删除、篡改、可疑扩展名、高敏感文件变化和批量变化拥有不同权重。敏感关键词、高敏感等级、可疑扩展名、文件大小变为 0 等证据会提高分值。最高分限制为 100。

## 安全边界

系统只允许操作 `demo_workspace/protected_files`，不扫描系统目录，不访问外网，不执行脚本，不实现攻击行为。所有路径都必须进行相对路径校验，恢复路径禁止 `../` 和绝对路径。

## 为什么使用文件哈希基线

哈希基线能够精确表示文件内容状态。即使文件大小不变，只要内容改变，SHA-256 也会变化，因此适合检测篡改。删除和新增也可以通过路径集合差异发现。

## 为什么使用备份恢复验证

备份只能说明有可恢复来源，恢复后还必须证明文件内容与基线一致。恢复验证通过重新计算 SHA-256 并与基线哈希比较，能够证明恢复结果可信。

## 为什么适合风险展示

本项目将抽象的文件风险转化为可观察的事件、分值、等级、证据、建议和报告页面，适合课堂演示、截图和后续 PDF 报告撰写。
