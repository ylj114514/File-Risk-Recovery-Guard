# 风险案例文档

## 案例 1：账号文件被异常删除

风险对象：`account_list.txt`，模拟账号清单文件。  
触发条件：执行删除模拟后，当前扫描结果中该路径不存在，但基线中存在。  
风险证据：事件类型为 `DELETED`，`old_hash` 存在，`new_hash` 为空，文件敏感等级为 `HIGH`，路径包含 `account` 敏感关键词。  
影响分析：账号清单被删除会导致资料不可用，也会影响后续审计和恢复。  
风险分值：通常达到 80 分以上，受删除、高敏感等级、敏感关键词和高敏感删除额外规则影响。  
风险等级：`CRITICAL`。  
防护建议：立即从备份恢复文件，核查删除来源，限制敏感目录写入权限，保留操作日志。

## 案例 2：财务文件被篡改

风险对象：`finance_report.txt`，模拟财务报告文件。  
触发条件：执行篡改模拟后，文件仍存在，但当前 SHA-256 与基线 SHA-256 不一致。  
风险证据：事件类型为 `MODIFIED`，`old_hash` 与 `new_hash` 不同，文件敏感等级为 `HIGH`，路径包含 `finance` 敏感关键词。  
影响分析：财务文件被篡改可能造成错误决策、数据污染和审计风险。  
风险分值：通常为 80 分以上，受篡改、高敏感等级、敏感关键词和高敏感篡改额外规则影响。  
风险等级：`CRITICAL`。  
防护建议：从可信备份恢复或人工复核内容，确认修改来源，必要时冻结写权限。

## 案例 3：多个敏感文件批量变化

风险对象：`finance_report.txt`、`contract_2025.txt`、`project_plan.txt` 等多个文件。  
触发条件：一次扫描中检测到 3 个及以上文件出现删除、新增或篡改。  
风险证据：事件类型包含 `BULK_CHANGE`，`change_count` 达到阈值，并伴随多个高敏感文件变化。  
影响分析：批量变化可能来自误操作、异常程序或未授权批量写入，影响范围更大。  
风险分值：通常达到 `HIGH` 或 `CRITICAL`，受批量变化、敏感等级和基础事件规则影响。  
风险等级：`HIGH` 或 `CRITICAL`。  
防护建议：立即停止批量写入来源，导出风险报告，逐项恢复关键文件并复核操作来源。
